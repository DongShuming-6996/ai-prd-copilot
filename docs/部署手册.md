# AI PRD Copilot 部署手册（作品集上线）

> 当前版本为 PRD 撰写与管理工具，**已移除 AI 功能**；本文档中 AI 代理（Vercel Function / 腾讯云云函数）相关步骤不再需要，仅保留静态部署部分。

目标：把本地应用发布上线，访客打开链接即可使用；API Key 只存在服务端，前端零配置。

架构：

- 前端：纯静态 SPA（`index.html` + `css/` + `js/`）→ **GitHub Pages 主站**（国内可访问），Vercel 作为海外备用
- AI 代理：Key 只放服务端；本地用 `server.js`，上线用腾讯云云函数（或 Vercel Function 备用），前端通过 `js/config.js` 的 `AI_API_BASE` 指向代理
- 数据：当前版本用浏览器 localStorage；Supabase 持久化为阶段 2（可选）
- 域名：腾讯云域名 CNAME 到 GitHub Pages（或云函数 API 网关）
- 代码：GitHub 仓库，可选 GitHub Actions 自动部署

---

## 第 1 步：GitHub 仓库

1. 打开 https://github.com/new 创建仓库（建议 `ai-prd-copilot`，公开或私有皆可，作品集建议公开）。
2. 在仓库页复制远程地址（HTTPS 或 SSH）。
3. 本地推送（在 `ai-prd-copilot` 目录执行）：

```bash
git init
git add .
git commit -m "feat: AI PRD Copilot 初版"
git branch -M main
git remote add origin <你的仓库地址>
git push -u origin main
```

> 注意：`.gitignore` 已排除 `.env*`，推送前确认没有把任何密钥提交进仓库。

## 第 2 步：部署

> 重要说明：`*.vercel.app` 在国内网络经常无法访问（实测超时）。**主站用第 2A 步的 GitHub Pages**，Vercel 仅作为海外访问备用，可跳过。

### 第 2A 步：GitHub Pages（主站，推荐）

1. 仓库已在 GitHub：https://github.com/DongShuming-6996/ai-prd-copilot；
2. 打开仓库 → **Settings → Pages** → Build and deployment → Source 选 **Deploy from a branch** → Branch 选 `main`，目录选 `/ (root)` → Save；
3. 等 1~2 分钟，站点地址：https://dongshuming-6996.github.io/ai-prd-copilot/
4. 打开验证：页面正常、Demo 模式可用（无服务端时自动回退，顶栏显示 Demo 模式是预期行为）。

> 仓库根目录已包含 `.nojekyll`，GitHub Pages 不会按 Jekyll 处理，静态资源路径正常。

### 第 2B 步：Vercel（海外备用，可选）

方式 A（最简单，推荐）：Vercel 网页端导入

1. 打开 https://vercel.com/new → Import Git Repository → 选刚推送的 GitHub 仓库；
2. Framework Preset 选 Other；Root Directory 默认（仓库根目录）；
3. 点 Deploy，等构建完成；
4. 进入项目 → Settings → Environment Variables，添加：
   - `OPENAI_API_KEY` = 你的 Key（Production + Preview + Development 都加上）
   - （可选）`ALLOWED_ORIGINS` = `https://你的域名`（来源校验，防止被别处调用）
5. 重新 Deploy（或改代码 push 触发），完成后打开部署域名验证。

方式 B：CLI 部署

```bash
vercel login
vercel link          # 关联/创建项目
vercel env add OPENAI_API_KEY production   # 粘贴 Key
vercel --prod
```

验证：

- 打开 `https://<项目名>.vercel.app`，顶栏徽标应显示「真实模型模式 · 服务端 Key」；
- 生成一份 PRD 确认真实模型链路可用；
- 若显示 Demo 模式，说明环境变量没生效（重新 Deploy 或检查 Settings → Environment Variables）。

## 第 3 步：腾讯云域名绑定

1. 到腾讯云 DNS 控制台，给域名（如 `prd.example.com`）加一条 **CNAME** 记录，指向 `dongshuming-6996.github.io`；
2. 等 DNS 生效（几分钟到几小时），访问 `https://prd.example.com/ai-prd-copilot/` 验证；
3. 若 GitHub Pages 域名解析不稳定，也可改用腾讯云 COS 静态托管 + 腾讯云域名。

### 第 3A 步（真实模型 · 国内可访问）：腾讯云云函数代理

1. 腾讯云控制台 → 云函数 SCF → 新建函数：运行时 **Node.js 18+**，创建方式选"本地上传 ZIP"；
2. 打包上传：`tencent-scf/index.js` + `lib/ai-proxy.js` + `js/demo.js`（保持相对路径，函数入口 `index.main_handler`）；
3. HTTP 触发器用 API 网关（或函数 URL），发布后得到代理地址；
4. 函数环境变量配置：
   - `AI_API_BASE` = `https://api.deepseek.com`
   - `AI_API_KEY` = 你的 DeepSeek Key
   - `AI_MODEL` = `deepseek-chat`（或 `deepseek-reasoner`）
   - `USAGE_LIMIT` = `5`（每个 IP 每日生成次数）
5. 前端：修改 `js/config.js` 的 `window.AI_API_BASE` 为云函数地址，`git push` 重新发布 GitHub Pages；
6. 验证：顶栏徽标变「真实模型模式 · 服务端 Key」，生成时每次扣 1 次额度。

## 第 4 步（可选 · 阶段 2）：Supabase 数据持久化

当前版本数据存浏览器 localStorage，作品集演示够用。若要多人共享数据：

1. 打开 https://supabase.com → New Project；
2. SQL Editor 中执行 `supabase/schema.sql`（建 `projects` / `user_settings` 表，已启用 RLS）；
3. 前端接入 supabase-js（Auth + 读写 `projects` 表），把 localStorage 读写替换为数据库调用；
4. 若想用 Supabase Edge Function 替代 Vercel Function 做 AI 代理，可复用 `lib/ai-proxy.js` 的逻辑迁移到 `functions/`，Key 放 Secrets。

- [ ] 匿名访客无需任何配置即可生成 PRD

## 常见问题

- **部署后仍 Demo 模式**：环境变量没配或没生效 → Settings → Environment Variables 检查，重新 Deploy。
- **API 返回 500**：看 Vercel 项目 Logs（`vercel logs`），通常是 Key 无效或模型名不对。
- **刷新页面 404**：检查 `vercel.json` 的 rewrite 是否生效（`/((?!api/).*)` → `/index.html`）。
- **CI 部署失败（GitHub Actions）**：需要 Vercel Account → Settings → Tokens 创建 `VERCEL_TOKEN`，加到仓库 Secrets；本地 `vercel link` 后把 `.vercel/project.json` 提交到仓库。
- **推送被拒 `refusing to allow a Personal Access Token to create or update workflow`**：`.github/workflows/` 下的文件需要 Token 具备 `workflow` 权限。不启用 Actions 时直接删除该目录即可（模板已保留在 `docs/github-actions-deploy.yml`）；想启用 Actions 就去 GitHub → Settings → Developer settings → Tokens 重新生成带 `workflow` scope 的 Token。
